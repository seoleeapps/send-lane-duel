## 타깃과 플랫폼

- 1차 타깃 가설: 디펜스·전략 캐주얼을 해 본 20~40대. 실시간 대전의 압박과 과금 경쟁 없이 머리싸움을 하고 싶은 사람. DEC-002에서 확정했다.
- 근거: 직접 경쟁작 리뷰의 반복 불만이 "돈을 써야 이긴다", "강제 광고", "1인 플레이인데 온라인 필수"다(`01-research-dossier.md` SRC-002, SRC-007).
- 기기: Android 9 이상·iOS 15 이상을 가정한다. 최소 화면 360×640dp, 대표 390×844pt, 최대 폴더블 펼침은 세로 중앙 정렬.
- 언어: 영어, 한국어. 문자열은 처음부터 분리한다.
- 대상 연령: 13세 이상으로 선언한다(POL-002). 아동 대상 아님.

## 플레이어 판타지와 제품 기둥

판타지: 상대 지휘관의 버릇을 읽고, 정확히 넘칠 만큼만 보내서 성을 무너뜨리는 책사.

| 기둥 | 뜻 | 지키는 방법 |
| --- | --- | --- |
| 한 번의 나눔 | 매 판의 결정은 금화를 세 갈래로 나누는 것 하나다 | 화면의 가장 큰 조작부는 세 갈래 배분이다. 다른 메뉴를 판 중에 열지 않는다 |
| 읽히는 상대 | 지휘관은 성향대로 움직이고, 방어는 보이고 보낼 용병만 숨겨진다 | 지휘관 6종의 규칙을 도감에 그림으로 공개한다. 지휘관은 내 이번 판 선택을 훔쳐보지 않는다 |
| 진 이유가 보인다 | 패배 화면이 "어느 용병이 어느 자리에서 샜는지"를 그림으로 보여 준다 | 전투는 난수가 없다. 같은 입력이면 같은 결과다 |
| 힘을 팔지 않는다 | 광고와 메타는 런 안의 힘을 주지 않는다 | 결제 상품이 없다. 일일 도전은 이어하기 없이 모두 같은 조건 |
| 광고는 쉬는 곳에서만 | 전면 광고는 판 도중과 전투 중에 나오지 않는다 | 장 보상을 고른 뒤와 런 정산을 닫을 때만, 두 번째 세션부터, 세션 3회 한도, 5초 안에 닫힘 |

## 경험 타임라인

| 시점 | 플레이어가 겪는 것 |
| --- | --- |
| 10초 | 웨이브가 내 레인으로 들어오고, 내가 놓은 유닛이 막는다. 금화가 들어온다 |
| 3분 | 첫 지휘관의 성에 용병을 보내 처음으로 피해를 준다. 상대가 보낸 용병이 내 레인에 섞여 들어오는 것을 본다 |
| 10분 | 첫 런이 끝난다. 정산에서 지휘관 도감 한 칸이 열리고 진 이유를 본다 |
| 30분 | 3~4런. 지휘관 성향 두세 개를 알아보고, 길 선택에서 내 용병과 궁합이 좋은 지휘관을 고르기 시작한다 |
| 7일 | 편성 4개를 열고, 격(난이도 단계)을 올리고, 일일 도전에서 어제보다 높은 순위를 노린다 |

## 범위

출시 범위

- 원정: 4장, 지휘관 6종, 방어 유닛 4계열 × 3단계, 용병 8종, 증표 10종, 출정 편성 4종, 격 0~5
- 일일 도전: 하루 한 번 기록되는 시도, 상위 100과 내 순위
- 도감(지휘관·유닛·용병·증표), 설정, 체험형 튜토리얼(첫 런의 1장)
- 전면 광고 1곳(장 사이·런 사이), 보상형 광고 2곳, 분석, 저장 백업, 계정·데이터 삭제

범위 밖(출시 후 검토)

- 다른 사람의 기록과 겨루는 모드. 검산에서 같은 실력끼리도 살아 있는 쪽이 3~12배 유리했다(`../../sim/README.md` 상성 모델 절)
- 결제 상품(광고 제거 포함), 배너·앱 실행 광고, 앱인토스 출시, 길드·채팅, 실시간 대전

## 제작 제약과 팀

- 팀: 사람 1명 + 코딩 에이전트. 상시 운영 인력 없음.
- 아트·사운드는 생성 파이프라인(`game-asset-pipeline`, `game-sound-pipeline`)으로 만든다. 프레임 애니메이션 대량 제작은 하지 않는다.
- 콘텐츠는 표 기반이다. 새 지휘관·유닛·증표는 `data/content/*.json` 에 행을 더하고 `sim/run_sim.py` 로 검산한다.
- 서버는 문서 읽기·쓰기만 하고 유휴 비용이 0이어야 한다(`concepts/README.md` 역량 프로필).
